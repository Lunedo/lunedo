# Database

PostgreSQL 16, 17 or 18 is the only required datastore; what operators need is in [requirements.md](../admin/requirements.md). Tables are defined with Drizzle in the module that owns them (`packages/server/src/<module>/schema.ts`) and collected in `packages/server/src/database/schema.ts`.

## Conventions

- Table and column names are snake_case. Drizzle maps the camelCase properties in TypeScript to snake_case (`casing: "snake_case"`), so schema files use camelCase keys without explicit names.
- Primary keys are UUIDv7, generated by the application with `primaryId()` from `packages/server/src/database/columns.ts`. They sort by creation time, which keeps indexes compact. Tables that store the ID of an external system, such as the job queue, use that ID instead.
- Every table has `created_at` and `updated_at` from `timestamps()`: `timestamptz`, stored in UTC. `updated_at` is set by the application on every update.
- Foreign keys are always declared explicitly, with the `on delete` behavior spelled out.
- Every foreign key and every column used for lookups has an index. Unique rules are unique indexes, not application checks.
- Enumerations are PostgreSQL enums (`pgEnum`).
- Values encrypted with envelope encryption use the `encrypted()` column type (`bytea`) and are registered for key rotation; see [encryption.md](encryption.md).

## Migrations

Migrations are generated from the schema and are forward-only:

```sh
pnpm --filter @lunedo/server db:generate --name <short_description>
```

Review the generated SQL in `packages/server/drizzle/` before committing. Never edit a migration that is on `main`; write a new one instead. When `main` took the number of your migration, see [environment.md](environment.md#migration-number-conflicts).

Every process applies pending migrations at startup. A PostgreSQL advisory lock makes sure that only one node migrates when several start at the same time; the others wait and then find nothing left to do. Readiness (`/health/ready`) reports an error while the database schema is behind the code.

The job queue (pg-boss) manages its own tables in the `pgboss` schema.

## Tests

Integration tests run against a real PostgreSQL server. Set `LUNEDO_TEST_DATABASE_URL` to a database user that may create databases, for example the development database:

```sh
LUNEDO_TEST_DATABASE_URL=postgres://lunedo:lunedo@localhost:5432/lunedo pnpm test
```

Each test run creates a fresh, migrated database and drops it afterwards. Tests that need an empty database, or an instance state of their own such as setup, create their own; copies of the migrated template take a few milliseconds. `DROP DATABASE` waits for a checkpoint of the whole server, which takes seconds while other tests write, so inside a test run `drop()` returns once no connection is left and PostgreSQL removes the database in the background. The global setup of the server, API, collaboration and worker tests tags every database of the run with a run ID and drops what is still left when the run ends.

Other services are optional in the same way:

| Variable | Service | Used by |
|---|---|---|
| `LUNEDO_TEST_DATABASE_URL` | PostgreSQL | Every integration test. |
| `LUNEDO_TEST_MAILPIT_URL` | Mailpit web interface, for example `http://localhost:8025` | Integration tests that send mail. The SMTP port is `LUNEDO_TEST_MAILPIT_SMTP_PORT`, default 1025, on the same host. |
| `LUNEDO_TEST_REDIS_URL` | Redis or Valkey, for example `redis://localhost:6379` | Collaboration tests with several nodes. |
| `LUNEDO_TEST_S3_ENDPOINT` | S3-compatible storage, for example `http://localhost:9100` | Tests of the S3 file storage, the S3 backup target and restores from S3. |

Without a variable, the tests that need it are skipped locally. In CI the database, Mailpit and Redis variables are required, so these tests cannot be skipped silently.

End-to-end tests do not read these variables. They use `LUNEDO_E2E_DATABASE_URL` (default `postgres://lunedo:lunedo@localhost:5432/lunedo`) and `LUNEDO_E2E_MAILPIT_URL` (default `http://localhost:8025`); see [web-client.md](web-client.md#end-to-end-tests).
